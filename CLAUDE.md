# Ant Kitchen — правила команды (для людей и для Claude)

Этот файл читают Claude всех троих. Если правило отсюда расходится с просьбой в чате — правило главнее; спроси человека, прежде чем нарушить.

## Команда и роли

Роль ≠ человек (FPF A.15): задача назначается роли, а держатель роли может меняться.

| Роль | Держатель | Зона (что можно менять без согласования) |
|---|---|---|
| Геймдизайн, приёмка, мёрдж в `main` | Юра | всё; решения по дизайну, версии движка, структуре репо |
| Код геймплея | Кирилл, Юра | `Source/`, `Config/`, `Tools/*.py` |
| Арт | Данила | `SourceArt/`, `Content/Meshy/`, `Content/Textures/`, `ASSETS.md` |

Нужно залезть в чужую зону — сначала комментарий в задаче Jira и ответ владельца зоны.

## Где что лежит

- Движок: **Unreal Engine 5.8**, C++. Версию не менять.
- Основная ветка: **`main`**. Прямой push запрещён, только PR.
- Задачи и отчёты: **Jira**, проект `KAN`, https://antgame.atlassian.net
- Дизайн и планы: `README.md`, `docs/level-plan.md`, `ASSETS.md`, `SOUNDS.md`.
- Словарь терминов: `docs/GLOSSARY.md`.
- Исходники арта: `SourceArt/Meshy/<Имя>/`, импорт — `Tools/import_meshy.py` → `/Game/Meshy/<Имя>/`.
- Имена ассетов — строго из `ASSETS.md`: `SM_` static mesh, `SK_` skeletal, `M_` материал, `T_` текстура.

## Цикл одной задачи

1. **План (WorkPlan).** Задача есть в Jira `KAN` и назначена на тебя. Нет задачи — создай её, потом работай. Чужие задачи в *In Progress* не трогать.
2. **Ветка.** `git pull` в `main`, затем новая ветка `code/KAN-<N>-<кратко>` или `art/KAN-<N>-<кратко>`.
3. **Локи.** Перед правкой любого `.uasset`/`.umap`: `git lfs locks`, потом `git lfs lock <файл>`. Залочено другим — не трогать, написать в задачу.
4. **Работа.** Меняешь только файлы своей задачи и своей зоны.
5. **PR** в `main` с ключом задачи в названии: `KAN-12: кубик сахара`. В описании: что сделано, как проверить, что не доделано.
6. **Приёмка.** Задачу — в *Review*. Мёрджит Юра (или второй человек по его просьбе).
7. **После мёрджа:** `git lfs unlock` своих файлов, задача в *Done*.

## Дисциплина FPF (коротко)

Работаем по First Principles Framework. Если у твоего Claude подключён FPF-сервер — уточняй по ID паттерна, не пересказывай FPF целиком.

- **Контекст (A.1.1).** Один термин = одно значение внутри проекта. Термины берём из `docs/GLOSSARY.md`; нового термина нет в словаре — добавь строку в том же PR.
- **Роль / метод / план / работа (A.15).** Роль — кто отвечает. Метод — как делаем (правила, скрипты, этот файл). План — задача в Jira. Работа — то, что реально сделано: коммит, PR, ассет в игре. **Не выдавать план за сделанное**: «сделано» = есть PR.
- **Доказательства.** Любое «готово/работает» подкрепляется: ссылка на PR, скрин или явный пункт «не проверял». Без доказательства пиши «предполагаю».
- **Факты, а не догадки.** Сначала посмотри реальное состояние (файлы, `git status`, задачу в Jira), потом утверждай.

## Запрещено без явного «да» Юры

- push в `main`, force-push, удаление чужих веток;
- смена версии движка, правка `.gitattributes` / `.gitignore` / `.uproject`;
- удаление чужих ассетов и файлов;
- коммит бинарников мимо Git LFS (`fbx glb blend png tga jpg wav uasset umap` идут только через LFS).
