# Ant Kitchen — правила команды (для людей и для Claude)

Этот файл читают Claude всех троих. Если правило отсюда расходится с просьбой в чате — правило главнее; спроси человека, прежде чем нарушить.

## Команда и роли

Роль ≠ человек (FPF A.15): задача назначается роли, а держатель роли может меняться.

| Роль | Держатель | Зона (что можно менять без согласования) |
|---|---|---|
| Геймдизайн, приёмка, мёрдж в `main` | Юра | всё; решения по дизайну, версии движка, структуре репо |
| Код геймплея | Кирилл, Юра | `Source/`, `Config/`, `Tools/*.py` |
| Арт | Данила | `SourceArt/`, `Content/Meshy/`, `Content/Textures/`, `ASSETS.md` |

Нужно залезть в чужую зону — сначала комментарий в задаче Jira и ответ владельца зоны.

## Где что лежит

- Движок: **Unreal Engine 5.8**, C++. Версию не менять.
- Основная ветка: **`main`**. Прямой push запрещён, только PR.
- Задачи и отчёты: **Jira**, проект `ANT`, https://antgame.atlassian.net
- Дизайн и планы: `README.md`, `docs/level-plan.md`, `ASSETS.md`, `SOUNDS.md`.
- Словарь терминов: `docs/GLOSSARY.md`.
- Исходники арта: `SourceArt/Meshy/<Имя>/`, импорт — `Tools/import_meshy.py` → `/Game/Meshy/<Имя>/`.
- Имена ассетов — строго из `ASSETS.md`: `SM_` static mesh, `SK_` skeletal, `M_` материал, `T_` текстура.

## Цикл одной задачи

1. **План (WorkPlan).** Задача есть в Jira `ANT` и назначена на тебя. Нет задачи — создай её, потом работай. Чужие задачи в *In Progress* не трогать.
2. **Ветка.** `git pull` в `main`, затем новая ветка `code/ANT-<N>-<кратко>` или `art/ANT-<N>-<кратко>`.
3. **Локи.** Перед правкой любого `.uasset`/`.umap`: `git lfs locks`, потом `git lfs lock <файл>`. Залочено другим — не трогать, написать в задачу.
4. **Работа.** Меняешь только файлы своей задачи и своей зоны.
5. **PR** в `main` с ключом задачи в названии: `ANT-12: кубик сахара`. В описании: что сделано, как проверить, что не доделано.
6. **Приёмка.** Задачу — в *Review*. Мёрджит Юра (или второй человек по его просьбе).
7. **После мёрджа:** `git lfs unlock` своих файлов, задача в *Done*.

## Дисциплина FPF (коротко)

Работаем по First Principles Framework. Если у твоего Claude подключён FPF-сервер — уточняй по ID паттерна, не пересказывай FPF целиком.

- **Контекст (A.1.1).** Один термин = одно значение внутри проекта. Термины берём из `docs/GLOSSARY.md`; нового термина нет в словаре — добавь строку в том же PR.
- **Роль / метод / план / работа (A.15).** Роль — кто отвечает. Метод — как делаем (правила, скрипты, этот файл). План — задача в Jira. Работа — то, что реально сделано: коммит, PR, ассет в игре. **Не выдавать план за сделанное**: «сделано» = есть PR.
- **Доказательства.** Любое «готово/работает» подкрепляется: ссылка на PR, скрин или явный пункт «не проверял». Без доказательства пиши «предполагаю».
- **Факты, а не догадки.** Сначала посмотри реальное состояние (файлы, `git status`, задачу в Jira), потом утверждай.

## Запрещено без явного «да» Юры

- push в `main`, force-push, удаление чужих веток;
- смена версии движка, правка `.gitattributes` / `.gitignore` / `.uproject`;
- удаление чужих ассетов и файлов;
- коммит бинарников мимо Git LFS (`fbx glb blend png tga jpg wav uasset umap` идут только через LFS).

## Карта проекта (обязательно для агентов)

Вся игра разложена в живую карту: системы, фичи, персонажи, ассеты по частям (219 карточек Meshy), файлы, документы, статусы.
Источник правды: `project/map/*.yaml` и `project/map/assets_bible.json`. Сводка для чтения: `project/map/SUMMARY.md` (читай её в начале работы, чтобы не терять контекст).
Интерактивная страница (артефакт claude.ai): https://claude.ai/artifact/8rs9aDgofMHhTbwH2vu8Y5

После изменения систем, ассетов или статусов:
1. Поправь ручные данные: `project/map/systems.yaml` (системы и статусы), `manual.yaml` (решения, люди), `overrides.yaml` (точечные правки узла: status, owner, note).
2. `python Tools/projectmap/build_map.py` (нужен pyyaml; обновляет `map.json` и `SUMMARY.md`).
3. Закоммить `project/map/`, затем перепубликовать страницу: `data/map.json` артефакта = `project/map/map.json` (исходник страницы: `Tools/projectmap/viewer/index.html`).
4. Правки Юры со страницы лежат в базе артефакта, коллекция `edits`: прочитай, сохрани как JSON и влей через `python Tools/projectmap/apply_edits.py edits.json`.
Статусы систем: idea / designed / in-progress / in-game / polished / blocked / deprecated. Статусы ассетов: idea / prompt-ready / generated / imported / in-game / approved.

## Правила владельца (Юра, 26.11.2026) — обязательны для любой сессии и любого агента

1. **Ничего чужого.** В проект не добавляются бесплатные ассеты из интернета: ни модели, ни текстуры, ни звуки. Источники только свои: Blender-скрипты проекта, Meshy и Higgsfield с аккаунтов Юры. Уже лежащие чужие текстуры (Poly Haven, ambientCG — список в `docs/level/V4_CREDITS.md`) подлежат замене.
2. **Не подменять свои модели сгенерированными без спроса.** Замена существующей модели (в том числе через `SM_M4R_*`) делается только после того, как Юра увидел картинку «было / стало» и сказал «да».
3. **Не делать того, о чём не просили.** Новая модель, текстура, звук, перестановка на карте — только по задаче от Юры. Идея сверх задачи предлагается одной строкой, а не внедряется.
4. **Единый стиль.** Форма стилизована, материал честный; квартира правдоподобная: муравей лезет только по вещам, которые в обычном доме там и лежат.
5. **Всё двигается и ломается.** Новая вещь ставится через таблицу кухни (`level_v3_layout.py`), а не статичным декором; коллизия по форме.
6. **Учёт.** Каждая задача Юры заводится в Jira (проект KAN, https://antgame.atlassian.net) до начала работы и закрывается с номером сборки. Отчёт начинается со списка: что просили → что сделано → что нет.
7. **Показывать, а не описывать.** Изменение внешнего вида сдаётся со скриншотом из собранной игры (не из редактора: там нет света).
8. **Для команды — только публичное.** Инструкции и ссылки для друзей и команды лежат в репозитории или лаунчере, не в личных артефактах Claude.
